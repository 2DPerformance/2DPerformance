เริ่มจากข้อมูลต้นทางที่ตรวจสอบได้ แล้วค่อยอ่านผลลัพธ์และข้อจำกัดในบริบทของโครงการ

แบ่งงานให้มีขอบเขต เจ้าของ และผลส่งมอบที่ตรวจได้

ผูกลำดับและเวลา

กำหนด predecessor ระยะเวลา calendar และ milestone

อัปเดตรอบรายงาน

บันทึก actual progress และ cost ตามวันตัดยอดเดียวกัน

อ่านแนวโน้ม

ใช้ SPI, CPI และ S-Curve เป็นสัญญาณเพื่อทบทวนสาเหตุและ forecast

ข้อมูลที่ต้องเตรียม

  • WBS กิจกรรม ระยะเวลา และ calendar
  • ความสัมพันธ์ predecessor และ milestone
  • baseline budget และน้ำหนักงาน
  • actual progress, actual cost และ data date

ผลลัพธ์ที่ใช้ตรวจทานได้

  • Gantt และเส้นทางงานตามข้อมูลแผน
  • รายงานความก้าวหน้าเทียบ baseline
  • SPI, CPI และ S-Curve
  • forecast สำหรับทบทวนโดยทีมโครงการ

ขอบเขตและข้อจำกัดก่อนใช้ผล

  • ตัวชี้วัดขึ้นกับคุณภาพ baseline และวิธีวัด progress
  • forecast ไม่ใช่คำรับรองวันเสร็จหรืองบสุดท้าย
  • ต้องบันทึก data date และเหตุผลของการแก้ baseline
  • สถานะจากระบบไม่แทนการประชุมยืนยันกับผู้รับผิดชอบหน้างาน
หลักฐานไม่ใช่การอนุมัติ ผลและเอกสารจากระบบต้องผ่านการตรวจโดยผู้รับผิดชอบตามวิชาชีพและขอบเขตโครงการก่อนนำไปตัดสินใจหรือใช้ก่อสร้าง

คู่มือที่เกี่ยวข้อง

คู่มือเครื่องมือทั้งหมดพื้นวางบนดิน SL-04ฐานรากแผ่ FT-03ฐานราก 1 เสาเข็ม FT-02คานยื่นคอนกรีตหลักฐานผลคำนวณ

นายช่างใหญ่ Civil Apps เป็นพื้นที่ทำงานวิศวกรรมบนเว็บ ผลจากเครื่องมือต้องใช้ภายในขอบเขตที่ระบุและผ่านการตรวจโดยผู้รับผิดชอบก่อนนำไปใช้กับงานจริง
